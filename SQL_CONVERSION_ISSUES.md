# JSON to SQL Conversion - Potential Issues and Solutions

## Overview

This document outlines potential errors you may encounter when converting MongoDB JSON data to MySQL and how to resolve them.

---

## 1. Schema/Table Structure Issues

### 1.1 UUID vs Integer IDs

**Problem:** The MySQL models in `Apex_mySQL` use `INTEGER.UNSIGNED` with auto-increment for primary keys, but the existing `users_mysql.sql` and this conversion use UUID strings (CHAR(36)).

**Solution Options:**
1. **Option A (Recommended):** Update MySQL models to use UUID strings:
   ```javascript
   id: {
       type: DataTypes.STRING(36),
       defaultValue: DataTypes.UUIDV4,
       primaryKey: true
   }
   ```

2. **Option B:** Modify the conversion script to use auto-incrementing integers and create a separate mapping table for MongoDB ObjectId → MySQL integer ID.

### 1.2 Missing Columns in Models

**Problem:** Some columns generated by the conversion script may not exist in your MySQL models.

**Affected Tables:**
- `locked_coins_entries`: Columns `unclaimed_profit`, `last_claim_date`, `total_claimed_profit` may need to be added
- `withdrawals`: Column `transaction_id` (different from `withdrawal_id`) may need to be added

**Solution:** Update your Sequelize models or create ALTER TABLE statements:
```sql
-- For locked_coins_entries
ALTER TABLE locked_coins_entries 
ADD COLUMN unclaimed_profit DECIMAL(20,8) DEFAULT 0,
ADD COLUMN last_claim_date DATETIME,
ADD COLUMN total_claimed_profit DECIMAL(20,8) DEFAULT 0;

-- For withdrawals
ALTER TABLE withdrawals 
ADD COLUMN transaction_id VARCHAR(255);
```

## 2. Foreign Key Constraint Issues

### 2.1 Reference Integrity Errors

**Problem:** Foreign keys may reference users or records that don't exist.

**Affected Tables:**
- `bonus_transactions.stake_entry_id` → `locked_coins_entries.id`
- `withdrawals.processed_by` → `users.id`
- All tables with `user_id`, `from_user_id`, etc.

**Solution:** 
1. Import data with foreign key checks disabled:
   ```sql
   SET FOREIGN_KEY_CHECKS = 0;
   -- Import statements here
   SET FOREIGN_KEY_CHECKS = 1;
   ```

2. Import in correct order:
   1. `users` (first - no dependencies)
   2. `locked_coins_entries` (depends on users)
   3. All other tables

### 2.2 Missing User References

**Problem:** Some MongoDB documents may reference users that were deleted or don't exist in `users.json`.

**Detection:** The conversion script logs warnings for missing user references.

**Solution:** Either:
1. Add placeholder users for missing references
2. Set foreign key to NULL if the column allows it
3. Delete orphaned records

## 3. Data Type Issues

### 3.1 Decimal Precision

**Problem:** JavaScript floating-point numbers may have precision issues.

**Example:** `0.012000000000000002` instead of `0.012`

**Solution:** Truncate or round decimals in the conversion script:
```javascript
function escapeNumber(val) {
    if (val === null || val === undefined) return 0;
    return Number(Number(val).toFixed(8)) || 0;
}
```

### 3.2 Date/Time Timezone Issues

**Problem:** MongoDB stores dates in UTC, but MySQL may interpret them based on server timezone.

**Solution:** Ensure your MySQL connection uses UTC:
```sql
SET time_zone = '+00:00';
```

### 3.3 NULL vs Empty String

**Problem:** Some fields may be empty strings in MongoDB but should be NULL in MySQL.

**Solution:** The conversion script handles this, but verify ENUMs don't have empty string values.

## 4. Data Integrity Issues

### 4.1 Duplicate Transaction IDs

**Problem:** `transaction_id` and `withdrawal_id` fields are unique, but there might be duplicates.

**Solution:** Before importing, check for duplicates:
```sql
SELECT transaction_id, COUNT(*) as cnt 
FROM transactions 
GROUP BY transaction_id 
HAVING cnt > 1;
```

### 4.2 Orphaned Locked Coins Entries

**Problem:** `stakeEntryId` in `bonus_transactions` references `locked_coins_entries`, but the entry might not exist.

**Detection:** The conversion script validates these references.

**Solution:** Create missing locked coins entries or set `stake_entry_id` to NULL.

## 5. ENUM Validation Errors

### 5.1 Invalid ENUM Values

**Problem:** MongoDB may have values not defined in MySQL ENUM types.

**Affected Columns:**
- `users.role`: Expected values: 'user', 'admin'
- `transactions.status`: Expected: 'pending', 'approved', 'rejected'
- `withdrawals.status`: Expected: 'pending', 'processing', 'completed', 'rejected'
- `withdrawals.network`: Expected: 'BEP20', 'TRC20'
- `locked_coins_entries.status`: Expected: 'active', 'completed', 'unlock-pending', 'unlocked'

**Solution:** Validate all ENUM values before import or add new values to the ENUM:
```sql
ALTER TABLE withdrawals 
MODIFY COLUMN network ENUM('BEP20', 'TRC20', 'NEW_NETWORK');
```

## 6. Special Characters and Escaping

### 6.1 SQL Injection Prevention

**Problem:** Special characters in user data could break SQL statements.

**Affected Fields:**
- `full_name`
- `account_name`
- `note`
- `rejection_reason`

**Solution:** The conversion script escapes single quotes (`'` → `''`) and backslashes.

### 6.2 Unicode/UTF-8 Issues

**Problem:** Special characters may not display correctly.

**Solution:** Ensure MySQL uses UTF-8:
```sql
SET NAMES utf8mb4;
ALTER DATABASE your_database CHARACTER SET utf8mb4 COLLATE utf8mb4_unicode_ci;
```

## 10. Quick Fixes for Common Errors

### Error: "Duplicate entry for key 'PRIMARY'"
```sql
-- Option 1: Delete existing data first
TRUNCATE TABLE table_name;

-- Option 2: Use INSERT IGNORE
-- Modify INSERT INTO to INSERT IGNORE INTO
```

### Error: "Cannot add or update a child row: foreign key constraint fails"
```sql
SET FOREIGN_KEY_CHECKS = 0;
-- Run your INSERT statements
SET FOREIGN_KEY_CHECKS = 1;
```

### Error: "Data too long for column"
```sql
-- Check the column length
SHOW CREATE TABLE table_name;
-- Increase column size if needed
ALTER TABLE table_name MODIFY COLUMN column_name VARCHAR(1000);
```

### Error: "Incorrect datetime value"
```sql
-- Set SQL mode to allow zero dates
SET SQL_MODE = 'ALLOW_INVALID_DATES';
-- Or use NULL instead of invalid dates in conversion script
```
